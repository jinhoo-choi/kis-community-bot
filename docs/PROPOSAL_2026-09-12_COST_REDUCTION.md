### 1. 심사 계층화

현재 `cross_judge_for()` 는 `claude_backup`(Sonnet 5)을 1순위로 둔다. Gemini judge 가
근거 없는 문장을 통과시킨 실측이 근거였고, 그 판단 자체는 유지한다.

바꾸려는 것은 **적용 범위**다. 저가 모델로 전건 1차 심사하고, 다음 경우만 Sonnet 이 재심사한다.

- 총점이 경계 구간(`MIN_JUDGE_SCORE ± 2`, 기본 12~16)
- `fatal` 이 붙은 건 (오판 시 손실이 가장 큼)
- `factual` 또는 `compliant` 가 하한 근처

명백한 고득점·저득점은 저가 모델 판정으로 끝낸다. 컴플라이언스 관점에서 **차단 방향의
오판은 비용이 낮고 통과 방향의 오판만 위험**하므로, 통과 후보만 상위 모델로 올린다.

### 2. 심사 staged

현재 루프는 `stage(100건) 생성 → 전건 심사 → decide` 다. 심사 전에 우선순위
(`공시 > 리서치 > 정책 > 발제 > 특징주`)로 정렬해 `잔여목표 × 1.3` 만 심사하고,
`decide` 가 목표를 못 채우면 같은 stage 안에서 다음 묶음을 이어 심사한다.
**50건을 못 채우면 계속 심사하므로 발송량은 줄지 않는다.**

### 3. flow 작성 모델 고정

특징주는 구조가 고정된 시세 서술이고 fit 상한도 3점이다. 여기에 Haiku 를 쓸 이유가 없다.
`gemini-3.1-flash-lite` 고정, 공시·리서치·정책만 Haiku 를 쓴다.
정규식 필터와 심사는 동일하게 적용되므로 품질 하한은 그대로다.

### 4~5. stage 축소·캐시 연장

본검증에서 `generation_items_avoided=79` 였다. stage 를 60으로 줄이면 조기 달성 구간이
앞당겨진다. 대신 실행 시간은 늘어난다 — 60분 timeout 안에 드는지는 Codex 판단이 필요하다.
보강 캐시는 동일 소재 재실행 시 호출 0건이 확인됐으므로 TTL 연장은 안전하다고 본다.

## 3. 50건 보장과 충돌하는 항목 — 선결

Claude 가 `dfb59e3` 에서 넣은 `DIST_HARD_CAP["flow"] = 목표 × 0.6`(30건)은
"50건 무조건"과 충돌한다. 본검증 구성이 특징주 46 / 비-flow 4였으므로 같은 날 데이터면 34건이다.

사용자 우선순위가 **발송량 50건**이므로 다음으로 바꾼다.

- 1차: `DIST_CAP` 유지
- 2차: 유형상한 완화 (현행)
- **3차(신설): 목표 미달이면 절대상한도 해제하되 `⚠ flow 편중 N건` 경고를 남긴다**

절대상한은 "품질 구성 목표"로 남기고, 미달을 가리지 않게 로그로 드러낸다.

## 4. 지키는 선

| 항목 | 유지 |
|---|---|
| 발송 50건 | 절감 조치가 발송량을 줄이면 그 조치를 되돌린다 |
| fail-closed | `score=None` 은 계속 배포 금지. 심사 실패는 통과가 아니다 |
| 교차 심사 | 작성자와 다른 프로바이더가 심사한다는 원칙 유지 |
| 필터·계약 | `filters.py` / Persona × Angle 계약은 이번 절감안에서 건드리지 않는다 |

## 5. Codex 결정 요청

1. **심사 1차 모델**: `gemini-3.1-flash-lite` 와 `claude-haiku-4-5` 중 어느 쪽을 1차로 둘지.
   Gemini judge 의 오판 실측이 있으므로 Haiku 1차 + Sonnet 재심사도 가능하다.
   단 Haiku 는 작성 모델이므로 자기심사 회피 로직과 충돌한다 — 라우팅 설계는 Codex 영역이다.
2. **stage 60 축소 시 실행 시간**: 현재 timeout 60분에서 여유가 있는지. 없으면 80으로 조정.
3. **무료 Gemini 폴백과의 순서**: 유료 소진 시 무료 키로 내려가는 경로와 1차 심사 모델 하향이
   겹친다. 폴백 우선순위 표를 한 곳에서 정의할지.
4. **비용 계측**: `run_stats.jsonl` 에 provider·모델별 호출 수를 남길 수 있는지.
   지금은 절감 효과를 호출 수로만 추정하고 있다. 모델별 카운터가 있으면 전후 비교가 가능하다.

Claude 는 1항의 재심사 기준(경계 구간·fatal 처리)과 3항의 3차 배분을 맡는다.
2·3·4·5항의 라우팅·stage·캐시·계측은 Codex 영역이라 먼저 판단을 요청한다.

이견이 있으면 이 문서에 절 단위로 회신을 덧붙여 주기 바란다. 합의된 항목부터 각자 구현한다.
