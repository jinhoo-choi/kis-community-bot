## `#122` 실발송분에서 확인된 미해결 결함

발송 50건 전건이 필터 재검수를 통과하지만, **필터가 잡았어야 할 표현이 나갔다.**

| # | 내용 | 원인 |
|---|---|---|
| 1 | `이오테크닉스가 장중 고저 차이는 저가 대비 5.0%였네요` | 이중 주어 비문. `문장성분오류` 정규식이 `(변동폭\|고저차)(이었\|였습니다)` 만 잡아 `고저 차이는 … 였네요` 를 놓친다 |
| 2 | `제주반도체가 장중 저가 대비 5.9% 범위로 움직였습니다` | `장중범위표현오류` 정규식이 `(?:범위\|폭)(?:에서)?\s*움직` 이라 `범위로 움직` 을 놓친다 |
| 3 | 계약 **해지** 공시에 체결 용어 설명이 붙음 | `annotate_terms` 가 공시명 `단일판매ㆍ공급계약해지` 에서 체결 용어를 매칭한다 |

셋 다 재현 확인했고 수정하지 않았다. 1·2 는 정규식 보강이면 되고, 3 은
`annotate_terms` 의 매칭 범위 문제라 다른 유형에도 같은 오염이 있을 수 있다.

#24 는 **#18 이 만든 충돌**이다. 앵커를 늘리면 밀려나는 주장이 생기고, 그 주장이
다른 필터의 전제이면 새 충돌이 된다. 앵커를 추가할 때는 그 유형의 필터가 요구하는
주장이 무엇인지 함께 봐야 한다.

`tools/audit_contracts.py` 는 이 계열을 못 잡는다. 감사 범위가 전역 규칙 × 페르소나
× Angle 이라 facts 생성 코드와 필터·게이트 사이는 대상 밖이다. 넣어야 할 불변식:

1. facts 생성부가 만드는 모든 줄은 어떤 `CLAIM_SPEC` 에 매핑되거나, 매핑되지 않으면 프롬프트에서 제거돼야 한다
2. 각 `CLAIM_SPEC` 의 value 를 그대로 인용한 본문은 어떤 필터에도 걸리지 않아야 한다
3. `claims.select` 는 프롬프트 경로와 필터 경로에서 같은 집합을 내야 한다
4. `annotate_terms` 가 붙이는 사전 문구는 게이트 글감 판정과 `claims.build` 값 추출에서 빠져야 한다
5. **`ANCHOR_TYPES` 로 강제한 주장이, 같은 유형의 필터가 전제하는 주장을 밀어내지 않아야 한다** (#24)
